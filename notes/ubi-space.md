# 固件版刷机空间：UBI 块怎么算

GT-BE98 Pro 刷机时，新固件只能放进**备用号位 + 空闲块**。固件版比 KoolCenter 原版大，算错了就刷不进去。这里只记规则和查法。

## 规则（2026-11-07 实测，GT-BE98 Pro，NAND 256MB）

- 闪存的 `image` 分区是 UBI，按块分配，每块 126976 字节。
- 刷机程序给固件的每一段（bootfs、rootfs）各建一个卷，块数 = `ceil((字节 + 1MiB) / 126976)`。
  - 看起来是"大小加 1MiB 余量"。三次刷机、四个卷都正好对上：bootfs 114、rootfs 504、571、529。
  - 以前用的"取整 + 9"，最多多算 1 块。
- 两个号位（bootfs1+rootfs1、bootfs2+rootfs2）加上空闲块，一共 **1332 块**。
  - jffs、data、defaults 和坏块保留区，刷机都不碰。
- 刷机写的是**备用号位**，正在跑的那个号位不能动，所以要满足：

  **正在跑的固件块数 + 新固件块数 ≤ 1332**

- 每个固件都不超过一半（**666 块**），任何时候都能一次刷完。

## 查法

**固件要占多少块**（在电脑上）：

```sh
python3 -I rogui/fwbake.py blocks <新固件.pkgtb> [正在跑的固件.pkgtb]
```

给了第二个文件，它会直接告诉你这次放不放得下、剩几块。做固件时，`bake.sh` 的对比报告也会打印块数，超过一半给 ⚠️。

**路由器上还剩多少**（只读）。先看 `/proc/cmdline` 里正在跑哪个号位：是 `ubiblock0_6`，备用号位就是 bootfs1、rootfs1；是 `ubiblock0_4`，备用号位就是 bootfs2、rootfs2。

```sh
ssh <路由器> 'cat /proc/cmdline; u=/sys/class/ubi/ubi0; for v in $u/ubi0_*; do echo "$(cat $v/name) $(cat $v/reserved_ebs)"; done; echo "空闲 $(cat $u/avail_eraseblocks)"'
```

可用 = 空闲 + 备用号位的 bootfs + 备用号位的 rootfs。

| 102.8_0 固件版（不精简） | 685 |
| 102.9_0 固件版（不精简） | 693 |
| 102.9_0 固件版（精简，默认） | **643** |
| 102.9_0 固件版（精简 + 1MB squashfs 块，实验） | 596 |

- 当时路由器跑的是 102.8_0 固件版（685 块），留给新固件 647 块：
  - 精简版 643，放下了，实测从 1 号位启动；
  - 不精简的 693，差 46 块。
- 刷完以后，2 号位还是 102.8_0 固件版，空闲 4 块。下一次升级可用 4 + 114 + 571 = 689 块。
- ROG 网页每版让固件多出约 67 块；精简后只多约 17 块。
- KoolCenter 原版也在长：102.8 到 102.9 多了 8 块。

## 放不下时怎么办（从省事到折腾）

1. **精简**（默认开，`build.py --slim`）：删掉这台路由器用不到的网页文件，见 README 的「精简」。
2. **刷两次**：先刷 KoolCenter 原版，原版小，一般放得下。开机后正在跑的变成原版，再刷固件版。
3. **改用挂载版**：只刷原版，ROG 网页放 jffs，没有这个问题。
4. **squashfs 改成 1MB 块**（`ROGUI_SQFS_BLOCK=1048576`）：整个根文件系统压得更小，约 50 块。代价是不再是"只改了 /www"，而且没在路由器上开机验证过，只算实验。

## 注意

- 公式里的 1MiB 和 1332 都是这一台机器实测的。别的机器坏块多少不一样，空闲块可能差几块。余量只有个位数时，刷之前用上面的命令查一下实际值。
- 刷机程序发现放不下时应该会报错、不写入。这是读代码得出的，没实际试过，**不要拿它去试**。
